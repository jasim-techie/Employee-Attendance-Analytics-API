List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72-74) | Static `{"status": "ok"}` returned without checking MongoDB connectivity. If MongoDB is down, it returns 200 instead of 503. | Stop MongoDB or provide invalid `MONGO_URI`; `GET /health` still returns 200. | Executed `db.command("ping")`; on error or if `ok != 1`, raise `HTTPException(503, "Database unreachable")`. |
| 2 | `create_employee` (lines 79-84) | Race condition on duplicate `emp_code` due to check-then-insert (`find_one` followed by `insert_one`) without a DB unique index. | Send two concurrent `POST /employees` requests with identical `emp_code`; both return 201 and insert duplicate documents. | Added idempotent unique index on `emp_code` at startup (`uniq_emp_code`); caught `DuplicateKeyError` and raised HTTP 409. |
| 3 | `EmployeeIn` (lines 53-60) | Missing schema validations required by OpenAPI: `emp_code` pattern `^EMP\d{4,6}$`, email regex, valid date format for `joined_on`, and `shift_start != shift_end`. | Sending payload with `emp_code: "123"` or `shift_start: "09:30", shift_end: "09:30"` returns 201 instead of 422. | Replaced with `EmployeeCreate` using regex Field constraints and a model validator ensuring `shift_start != shift_end`. |
| 4 | `create_employee` / serialization (lines 81-85) | `created_at` set with `datetime.now()` (naive local time) and returned as datetime string rather than epoch milliseconds integer. | `POST /employees` response contains ISO datetime string for `created_at`, violating `EpochMillis` schema. | Stored UTC datetime truncated to seconds; converted to integer epoch milliseconds in `doc_to_employee_out`. |
| 5 | `list_employees` (lines 89-96) | Off-by-one pagination bug (`skip = page * page_size`), total counts entire collection ignoring filter, and missing required `emp_code` asc sort. | Requesting `page=1&page_size=20` skips the first 20 employees (starts at item 21); `total` with `department` query counts unfiltered employees. | Changed skip to `(page - 1) * page_size`, computed `total` using `db.employees.count_documents(q)`, and added `.sort("emp_code", ASCENDING)`. |
| 6 | `compute_late_minutes` (lines 33-37) | Grace period logic bug: converts to integer minutes first (`int(seconds / 60)`), so `09:40:01` yields 10 which fails `minutes > 10`, incorrectly returning 0 late minutes instead of 10. Also lacks IST timezone awareness and R1 sub-second truncation. | Input punch at `09:40:01` for shift `09:30` returns 0 instead of 10. | Converted punch to IST, calculated difference in seconds against shift start in IST, and checked `if diff_sec > 600: return int(diff_sec // 60)` else 0. |
| 7 | `compute_work_hours` (lines 40-41) | Uses Python's built-in `round()`, which applies banker's rounding (round-half-to-even) rather than half-up rounding (R4). | E.g., a duration yielding midpoint float ending in `.005` rounds to even instead of up. | Implemented `Decimal.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`. |
| 8 | `compute_overtime` (lines 44-47) | Uses `max(0, int(...))` which awards overtime for any positive minutes (< 30), violating R3 requirement of minimum 30 minutes threshold. Also fails overnight shifts where `shift_end` is next day. | Punch-out 5 minutes after shift end gives 5 overtime minutes instead of 0. Overnight shift ends on same date. | Checked `diff_sec >= 1800` (30 min) before calculating floor minutes; added 1 day to `shift_end` calendar date when `shift_end <= shift_start`. |
| 9 | `punch_in` (lines 100-121) | Check-then-insert concurrency race on `(emp_code, date)`; unhandled `KeyError` (500) if employee not found; date determined by local time instead of IST; fails R1 overnight shifts; injects non-contract `"id"` field. | Concurrent punch-ins both return 201; punch-in for non-existent employee crashes with 500; overnight punch-in at 01:30 gets wrong date. | Created unique index on `(emp_code, date)` and handled `DuplicateKeyError` -> 409; checked employee existence (404); converted to IST with overnight shift rule; removed `"id"`. |
| 10 | `list_attendance` (lines 125-150) | In-memory processing: fetches all matching records via `list(db.attendance_logs.find(q))` and sorts in Python, causing severe latency and memory usage on 100k docs; missing sort by `emp_code` asc; missing `date_from > date_to` 422 check; injects `"id"` field. | Profiling query on 100,000 records shows collection scan and high RAM; `date_from=2026-07-10&date_to=2026-07-01` returns 200 with empty list instead of 422. | Delegated sort, skip, and limit directly to MongoDB index scan `[("date", -1), ("emp_code", 1)]`; added 422 validation for invalid date range; mapped records to contract schema. |
| 11 | Database initialization | No indexes created on startup; missing unique indexes on `employees.emp_code` and `attendance_logs.(emp_code, date)`, and compound indexes for queries. | Explain plans on endpoints show `COLLSCAN` and concurrent requests generate duplicate records. | Created all required indexes idempotently in FastAPI lifespan startup. |

### Examined and Decided NOT to be Defects
- **Use of synchronous PyMongo in FastAPI endpoints:** FastAPI executes synchronous `def` endpoints in Starlette's threadpool worker threads (`anyio.to_thread.run_sync`), ensuring database I/O does not block the main asyncio event loop. Using PyMongo with connection pooling keeps the architecture concise, reliable, and completely eliminates async event loop contention.
- **Handling of absent/leave records:** The absence of punch-in and punch-out endpoints for `ABSENT` or `LEAVE` is not a defect; as stated in `DATA_MODEL.md` and `openapi.yaml`, `ABSENT` and `LEAVE` records are created by seed data or through regularization (`PATCH`), not punch events.
